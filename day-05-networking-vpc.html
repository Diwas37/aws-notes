Networking and the VPC

Your own private network inside AWS: how it is addressed, how traffic gets in and out, what filters it, and how it reaches other networks.

Day 05 · Networking VPC & subnets NAT & gateways Peering & endpoints Flow logs

What to remember

VPC is the backbone of Domain 1 and Domain 2. These five recur constantly.

  1. A subnet's CIDR can never be changed after creation, and neither can the VPC's. Size it generously the first time. → 02
  2. Public means one thing only: a route to an internet gateway. Private means a route to a NAT gateway instead. → 03
  3. NACL rules are numbered and first match wins; security group rules are all evaluated together. Only the NACL can deny. → 06
  4. VPC endpoints let private instances reach AWS services with no internet gateway, no NAT and no public IP. Usually the cost-optimisation answer. → 07
  5. Peering is not transitive and peered VPCs cannot have overlapping CIDRs. Many VPCs means a transit gateway. → 08

01 What a VPC is

A virtual private cloud is a network you define in software: address range, subnets, route tables and gateways.

  • Every account starts with a default VPC in each Region, which is why an instance launches and works with no setup at all.
  • A VPC lives in exactly one Region, and spans every Availability Zone in it.
  • A subnet lives in exactly one Availability Zone, and cannot straddle two.
  • Resources in one account's VPC are isolated from every other account by default.
Latency, roughly
BetweenExpect
Two instances in the same AZSingle-digit milliseconds, often well under one.
Two AZs in the same RegionLow tens of milliseconds at worst; usually one to two.
Two RegionsTens to hundreds, depending on distance.

These are the class's rough figures. The point they make is the one that matters: cross-AZ is cheap enough to design for high availability, cross-Region is not.

02 Addressing rules

Four rules, and the first is the one people regret.

The rules
RuleConsequence
The CIDR is fixed at creationYou cannot change a VPC's or a subnet's address range afterwards. You can add a secondary CIDR to a VPC, but the original never moves. Size it with room to grow.
Subnet CIDRs cannot overlapWithin a VPC, every subnet gets a distinct slice.
Smallest subnet is /2816 addresses, of which 11 are usable.
Largest subnet is /1665,536 addresses, 65,531 usable.

Five addresses are always reserved

In every subnet, whatever its size. For 10.0.0.0/24:

Reserved in every subnet
AddressReserved for
10.0.0.0Network address
10.0.0.1Internal communication — the VPC router
10.0.0.2DNS resolution
10.0.0.3Future use
10.0.0.255Network broadcast address

So a /24 gives 251 usable addresses, not 256 and not 254. A VPC of 10.0.0.0/16 split into four /24 subnets has 251 in each. Covered with the bit arithmetic on Day 01.

03 Public and private subnets

There is no "public" checkbox. A subnet is public because of one route, and nothing else.

Reachable Public subnet

  • Route table has 0.0.0.0/0 → internet gateway
  • Instances also need a public or Elastic IP of their own
  • Traffic flows both ways — no NAT involved
  • For load balancers, bastion hosts, NAT gateways

Outbound only Private subnet

  • No route to an internet gateway
  • Reaches out through a NAT gateway or NAT instance sitting in a public subnet
  • Nothing on the internet can start a connection inward
  • For databases, application servers, anything not public
Note What a public instance actually needs

Three things together, and missing any one breaks it: an internet gateway attached to the VPC, a route to it in the subnet's route table, and a public or Elastic IP on the instance. Security groups and NACLs then have to permit the traffic on top of that.

Where things belong
ResourceSubnetWhy
DatabasePrivateNothing outside should ever open a connection to it.
Load balancerPublicIt is the front door.
Web or app serversUsually privatePut them behind the load balancer; only it needs to be reachable.
NAT gatewayPublicIt needs its own route out to do its job.
Bastion hostPublicYou have to be able to reach it to jump from it.
Batch workersPrivateThey call out; nothing calls in.

04 NAT gateway and NAT instance

Two ways to give a private subnet a way out. One is managed, one is an EC2 instance you babysit.

Managed against self-run
 NAT gatewayNAT instance
AvailabilityHighly available within its AZ. Create one per AZ for resilience.You script your own failover between instances.
BandwidthScales to 45 GbpsWhatever the instance type gives
MaintenanceManaged by AWSYours — OS patches, software, the lot
CostPer hour plus per GB processedInstance cost plus network charges
Security groupsCannot have oneYes
Usable as a bastion hostNoYes
Caution Two traps

A NAT gateway cannot be used by instances in its own subnet — it serves other subnets that route to it. And it lives in one AZ: if that AZ fails, every private subnet pointing at it loses outbound access. Production designs put one in each AZ.

NAT instances are legacy. AWS's answer is the gateway; the instance only wins when you need a security group on it or want it to double as a bastion.

Note NAT gateways are a recurring cost answer

Billed per hour and per gigabyte processed. A private subnet pulling large volumes from S3 through a NAT gateway is paying twice over. The fix is a VPC endpoint, which routes that traffic privately and skips the NAT entirely.

05 Route tables and interfaces

A route table is a list of rules saying where traffic for a destination should go. An ENI is the virtual network card it arrives on.

Route tables

  • A subnet uses exactly one route table, though one table can serve many subnets.
  • A local route for the VPC CIDR always exists and cannot be deleted. It is what lets everything in the VPC talk to everything else.
  • The most specific match wins. A route for 10.0.5.0/24 beats 0.0.0.0/0.

Elastic network interfaces

An ENI is a virtual NIC. Each one can carry:

  • One primary private IPv4, and more secondary ones
  • One Elastic IP per private IPv4
  • One public IPv4
  • One or more security groups
  • A MAC address
Note ENIs move, but not between zones

An ENI can be detached from one instance and attached to another, carrying its addresses and security groups with it — handy for failover, since the address follows the interface. But an ENI is bound to the Availability Zone it was created in and cannot cross to another.

06 Security groups and NACLs

Two firewalls at two levels. Day 01 gave the summary; this is how the rules actually behave.

Security groups

  • Operate at instance level, strictly on the network interface.
  • An instance can have several, and there is no hierarchy or precedence between them — all rules are pooled and any match permits.
  • Stateful. Allow traffic inbound and the reply is permitted out automatically, and vice versa.
  • Allow rules only. There is no way to express a deny.

Network ACLs

  • Operate at subnet level, so they apply to every instance in the subnet automatically.
  • Rules are numbered 1 to 32766 and evaluated lowest first. The first match wins and evaluation stops.
  • Stateless. Return traffic needs its own rule, which is why outbound ephemeral ports must be open.
  • Support deny as well as allow — the reason to reach for one.
  • Every NACL ends with an implicit * rule that denies anything unmatched.
Caution Default NACL and new NACL behave oppositely

The default NACL that comes with a VPC allows all traffic both ways, so it is invisible until you change it. A newly created NACL denies everything until you add rules.

Attach a fresh NACL to a working subnet and everything stops instantly. This surprises people exactly once.

Good news Two conventions worth adopting

Number rules in hundreds — 100, 200, 300 — so there is room to insert one later without renumbering everything.

Leave the default NACL alone. Create a new one and attach it to the subnets that need it. Editing the default affects every subnet that has not been given its own, including ones added later by somebody else.

07 VPC endpoints

Reach AWS services from a private subnet without an internet gateway, a NAT, or a public IP anywhere.

Without an endpoint, an instance in a private subnet calling S3 goes out through the NAT gateway, across the public internet, and back into AWS. You pay NAT charges for traffic that never needed to leave.

Two kinds
 Gateway endpointInterface endpoint
How it worksAn entry in the route tableAn ENI with a private IP in your subnet
SupportsS3 and DynamoDB onlyMost other AWS services
CostFreePer hour plus per GB
Security groupsNo — controlled by endpoint policyYes, it is an ENI
Good news The gateway endpoint is free money

S3 and DynamoDB gateway endpoints cost nothing and remove NAT charges for that traffic entirely. If a question mentions private instances, heavy S3 traffic, and a cost concern, this is almost always the answer.

08 Connecting VPCs

Three ways to join networks, and the first has a limit that forces the third.

One to one VPC peering

  • A direct link between two VPCs, same or different account, same or different Region
  • Traffic stays on the AWS network
  • Not transitive — A↔B and B↔C does not give A↔C
  • CIDRs must not overlap, or the peering fails

Shared subnets VPC sharing

  • One account owns the VPC, others launch resources into its subnets
  • Fewer VPCs to manage, less duplicated networking
  • Resources stay owned by their own accounts

Hub and spoke Transit gateway

  • A central hub every VPC connects to once
  • Replaces a mesh of peerings
  • Much less to manage as the count grows
  • Also terminates VPN and Direct Connect
Caution Why peering stops scaling

Peering is not transitive, so connecting everything to everything needs a full mesh. Four VPCs need 6 peerings; ten need 45. The formula is n(n−1)/2, and it is why "we have many VPCs" almost always means transit gateway on the exam.

09 Reaching on-premises

Three options for hybrid. The difference is whether the traffic crosses the public internet.

Hybrid connectivity
OptionPathFor
Site-to-Site VPNOver the internet, in an encrypted tunnelQuick to set up, cheap. Bandwidth and latency vary with the internet.
VPN CloudHubOver the internet, hub and spokeSeveral sites connecting to AWS and to each other through it.
Direct ConnectA private physical link, never the internetConsistent latency and high throughput. Weeks to provision, and it costs.

A Site-to-Site VPN has two ends: a virtual private gateway on the AWS side and a customer gateway representing your router. Direct Connect uses a dedicated line, presented as an 802.1Q VLAN.

Note Private subnets can reach on-premises directly

A private subnet does not need a public subnet or a NAT to talk to your data centre. The route goes to the virtual private gateway, which is not an internet path, so the subnet stays private while still reaching internal systems.

Good news The exam shorthand

Needs it working today, or as a backup → VPN. Needs consistent performance for steady heavy traffic → Direct Connect. Wants both → Direct Connect with a VPN as failover, which is the standard resilient answer.

10 Bastion hosts

A single hardened door into private instances, so they need no exposure of their own.

  • Sits in a public subnet and is the only thing reachable from outside.
  • You SSH to it, then from it to the private instances.
  • The private instances' security group should allow SSH from the bastion's security group, not from an IP range — so it keeps working as the bastion is replaced.
  • Lock the bastion's own inbound rule to your office or VPN addresses.
Note The modern alternative

AWS Systems Manager Session Manager gives shell access to private instances with no bastion, no open SSH port and no key pairs, logging every session. If a question stresses removing SSH exposure or auditing access, that is the answer rather than a better-configured bastion.

11 Seeing the traffic

Two tools. One records that a connection happened; the other captures what was in it.

Metadata VPC flow logs

  • Records source, destination, ports, protocol, bytes, and accept or reject
  • Not the packet contents
  • Capture at VPC, subnet or ENI level
  • Publish to CloudWatch Logs, S3, or Data Firehose
  • The first stop for "why is this connection refused"

Full packets Traffic mirroring

  • Copies actual packets from an ENI to a monitoring appliance
  • For deep content inspection and threat detection
  • Far more data, and far more cost
  • Used when metadata is not enough
Good news Flow logs answer the commonest question

A rejected entry tells you traffic was blocked by a security group or NACL; an accepted one tells you it got through and the problem is further up. That single distinction resolves most connectivity debugging, and it is why flow logs are worth turning on before you need them.

Flow log destinations can feed onward into Athena for querying, QuickSight for dashboards, or an alerting pipeline — the class listed S3, CloudWatch, Kinesis, SNS, Athena and QuickSight as the usual landing spots.

12 Lab ahead: build a VPC

Module 7's guided lab, flagged in class as the next session's demo. Not done yet.

Everything on this page is about to be assembled by hand. Worth knowing the order before starting, because each step depends on the one before it:

  1. Create the VPC with a CIDR — and size it properly, because it cannot be changed later.
  2. Create subnets, at least one public and one private, in different Availability Zones.
  3. Create an internet gateway and attach it to the VPC. Creating it is not enough; it has to be attached.
  4. Edit the public subnet's route table: add 0.0.0.0/0 → internet gateway. This is the step that makes it public.
  5. Create a NAT gateway in the public subnet, with an Elastic IP.
  6. Point the private subnet's route table at 0.0.0.0/0 → NAT gateway.
  7. Create security groups, then launch instances and confirm the private one can reach out but cannot be reached.
Caution Where this usually goes wrong

Three failures account for most of them: the internet gateway is created but not attached; the route table is edited for the wrong subnet; or the NAT gateway is placed in the private subnet, where it cannot reach the internet to do its job.
