Networking, Virtualization and Linux

The groundwork under everything else: how an address is built, how packets are routed and filtered, how one machine becomes many, and how to drive the Linux box at the end of it.

Day 01 · Basics IP & subnets TCP/IP & ports Routing & NAT Hypervisors Linux

What to remember

This day is fundamentals, so most of it is assumed rather than asked, but these five turn into questions directly.

  1. A subnet lives in exactly one Availability Zone, and AWS reserves 5 addresses in every subnet regardless of size. → 02
  2. Security groups are stateful and allow-only; NACLs are stateless and can deny. To block a single malicious IP, only a NACL can do it. → 07
  3. Public subnet = a route to an internet gateway. Private subnet = a route to a NAT gateway. That route is the entire difference. → 08
  4. ALB is layer 7, NLB is layer 4. Questions about paths and hostnames mean ALB; questions about raw TCP throughput or static IPs mean NLB. → 04
  5. An SSH key file must be chmod 400, or the client refuses to use it. The single most common first-connection failure. → 11

01 How an IP address is built

An IPv4 address is 32 bits. Everything else about subnetting follows from that one number.

Those 32 bits are written as four 8-bit groups in decimal, which is why each part runs 0 to 255. Take the address from the Day 02 lab:

What the slash means

CIDR notation writes the prefix length after a slash. /24 means the first 24 bits are fixed. Subtract from 32 and you get the free bits, and two to that power is how many addresses the block holds.

Prefix arithmetic
CIDRFixed bitsFree bitsTotal addressesUsable in AWS
/161616216 = 65,53665,531
/202012212 = 4,0964,091
/2424828 = 256251
/2828424 = 1611
Note Smaller number, bigger network

This trips everyone up at first. A /16 is larger than a /24, because fewer fixed bits leaves more free ones. Fewer fixed bits, more room.

Private ranges

Three blocks are reserved for private networks and are never routed on the public internet. Your VPC will use one of them, which is why the lab instance answered to 172.31.40.217 and not something reachable from outside.

RFC 1918 private ranges
BlockRangeWhere you see it
10.0.0.0/810.0.0.0 – 10.255.255.255The usual choice for a custom VPC. Largest of the three.
172.16.0.0/12172.16.0.0 – 172.31.255.255AWS default VPCs live here, at 172.31.0.0/16.
192.168.0.0/16192.168.0.0 – 192.168.255.255Home routers, mostly.

02 Subnets, and the five AWS takes

A VPC is a private network you own. Subnets slice it up, usually one per Availability Zone.

AWS takes five addresses from every subnet

Not four, not two. Five, in every subnet, whatever its size. In a 10.0.0.0/24:

Reserved in every subnet
AddressTaken for
10.0.0.0The network address itself.
10.0.0.1The VPC router.
10.0.0.2DNS. Always the base of the VPC range plus two.
10.0.0.3Reserved by AWS for future use.
10.0.0.255Broadcast. VPCs do not support broadcast, but the address is reserved anyway.
Caution This bites on small subnets

A /28 holds 16 addresses and gives you 11. AWS will not let you create anything smaller than a /28, or larger than a /16, for exactly this reason. If an exam question asks how many instances fit in a subnet, subtract five.

Public, private and elastic addresses

Three kinds of address
KindBehaviour
Private IPFrom the subnet range. Stays with the instance for its whole life. Not reachable from the internet.
Public IPAssigned from AWS's pool. Released and re-drawn every time the instance stops and starts, so it is not something you can point DNS at.
Elastic IPA static public IPv4 you allocate and keep. Survives stop/start, and can be moved to another instance during a failover. This is the "fixed IP" from the class notes.
Note Elastic IPs are charged when idle

AWS bills for an Elastic IP that is allocated but not attached to a running instance. The pricing is deliberately backwards to discourage hoarding scarce IPv4 addresses.

03 TCP and UDP

Two ways to send data. One checks it arrived, the other does not.

TCP against UDP
 TCPUDP
ConnectionHandshake before any data movesNone. Just sends.
DeliveryGuaranteed. Lost packets are retransmitted.Best effort. A lost packet is simply gone.
OrderReassembled in orderMay arrive out of order
OverheadHigher — acknowledgements, sequence numbers, windowMinimal
SpeedSlowerFaster
Used byHTTP, HTTPS, SSH, SMTP, database connectionsDNS lookups, video streaming, voice, gaming
Note The three-way handshake

TCP opens with SYN → SYN-ACK → ACK. Three messages before a single byte of payload. That round trip is exactly what UDP skips, and exactly why a dropped video frame is preferable to a stalled call.

04 OSI and TCP/IP

Two models of the same thing. OSI has seven layers and is the teaching model; TCP/IP has four and is what actually runs.

The two models side by side
LayerOSITCP/IPCarriesIn AWS
7ApplicationApplicationHTTP, DNS, SSHALB routes here — on paths and hostnames
6PresentationTLS, encoding, compressionCertificates from ACM
5SessionOpening and closing conversations—
4TransportTransportTCP, UDP, port numbersNLB routes here — raw TCP, very fast
3NetworkInternetIP addresses, routingRoute tables, NACLs
2Data linkNetwork accessMAC addresses, Ethernet framesElastic network interfaces
1PhysicalCables, radio, lightEntirely AWS's problem
Caution Layer 7 versus layer 4 is an exam favourite

If a question mentions routing by URL path, hostname, or HTTP header, the answer is an Application Load Balancer (layer 7). If it mentions extreme throughput, static IP addresses, or a protocol that is not HTTP, the answer is a Network Load Balancer (layer 4).

DNS turns a name into an address. HTTP is what you then say to it.

Caution ALIAS versus CNAME shows up constantly

You cannot put a CNAME on the root of a domain. So when a question wants example.com (not www.example.com) pointed at a load balancer or CloudFront distribution, the answer is a Route 53 ALIAS record.

07 Controlling access

Two firewalls at two different levels, behaving differently. Knowing which is which is worth several marks.

Security group vs NACL
 Security groupNetwork ACL
Attaches toAn instance, strictly its network interfaceA whole subnet
StateStateful. Allow traffic out and the reply comes back automatically.Stateless. The reply needs its own rule.
Rule typesAllow only. There is no deny.Allow and deny
EvaluationAll rules considered together; any match permitsIn rule-number order, lowest first, first match wins
DefaultBlocks all inbound, permits all outboundThe default NACL permits everything both ways
Applies toOnly the instances it is attached toEverything in the subnet, automatically
Danger Only a NACL can block

Security groups have no deny rule. So when a question describes one specific IP address attacking you and asks how to shut it out, a security group cannot express that. The answer is a NACL deny rule.

The flip side: because NACLs are stateless, allowing inbound 443 is not enough on its own. The reply leaves from an ephemeral port, so outbound 1024–65535 has to be allowed too, or the connection hangs.

Good news Security groups can reference each other

A rule's source can be another security group rather than an IP range. "Allow 3306 from the web-tier security group" keeps working as instances come and go, with no addresses to maintain. It is the idiomatic answer for tier-to-tier access.

08 Routing and NAT

A subnet is public or private purely because of one line in a route table. Nothing else distinguishes them.

Route table entries
DestinationTargetEffect
10.0.0.0/16localAlways present, cannot be deleted. Lets everything in the VPC reach everything else.
0.0.0.0/0igw-…Makes the subnet public. Two-way internet, for instances that also hold a public or Elastic IP.
0.0.0.0/0nat-…Makes the subnet private. Outbound only.
Gateway against gateway
 Internet gatewayNAT gateway
Attaches toThe VPC. One per VPC.A subnet — and it must be a public one.
DirectionBoth waysOutbound only
NeedsInstances to have their own public IPIts own Elastic IP
CostFreeHourly charge plus per GB processed
AvailabilityRegion-wide, managedLives in one AZ. For resilience you need one per AZ.
Caution NAT gateways are a cost-question favourite

They are billed per hour and per gigabyte, so a chatty private subnet gets expensive quietly. When a cost-optimisation question involves private instances pulling large amounts of data from S3, the answer is usually a VPC gateway endpoint, which routes that traffic privately and skips the NAT gateway entirely.

09 Virtualization

One physical machine presented as many. A hypervisor is what does the presenting, and there are two architectures.

Type 1: direct Ring 0 control

A bare-metal hypervisor is the operating system core, stripped down to do only one thing: schedule CPU cycles and map memory. It boots first and installs itself directly into the CPU's Ring 0, the most privileged level.

When a virtual machine tries to write to a disk or read memory, it executes a privileged instruction. The physical CPU catches this and triggers a VM-Exit. Because the Type 1 hypervisor sits at the lowest software layer, its own kernel logic catches that event instantly and uses native micro-drivers compiled into its kernel to run the command on real hardware, with nothing in between.

Type 2: translation through a host

A hosted hypervisor lives inside an ordinary operating system, so it is bound by that host's rules and scheduling. The host OS owns Ring 0. The hypervisor itself runs mostly in Ring 3 (user mode, where Chrome lives) and reaches privileged operations through a loaded kernel driver.

It cannot execute hardware instructions directly, so it must translate each one into a system call. Asked to write to a virtual disk, it effectively tells the host: "please write this block to C:\Users\VMs\ubuntu.vmdk using NTFS." The host's scheduler then decides when to get round to it, alongside every other process on the machine.

Which is which
 Type 1Type 2
Runs onThe hardware itselfOn top of an existing OS
Owns Ring 0YesNo — the host does
Hardware accessDirect, via its own driversTranslated into host system calls
PerformanceNear nativeNoticeably slower
ExamplesAWS Nitro, VMware ESXi, Xen, KVM, Hyper-VVirtualBox, VMware Workstation, Parallels
Used forData centres and cloudsRunning another OS on your laptop
Note Your EC2 instance is on a Type 1

Modern EC2 runs on the AWS Nitro hypervisor, which is Type 1 and offloads networking and storage onto dedicated hardware cards. That is why an instance can reach close to bare-metal performance, and it is the reason "virtualization" appears on the provider's side of the responsibility line for IaaS.

Almost every server you will touch runs Linux, and the exam quietly assumes you can find your way around one.

Using the wrong username is the most common reason a first SSH attempt fails. The error looks like a key problem and is not.

Why the cloud runs on Linux

  • No per-instance licence. Autoscaling from 3 to 300 machines costs nothing extra in licensing.
  • Small. A server image with no desktop boots in seconds and leaves the RAM to your application.
  • Scriptable end to end. Anything you can do by hand you can put in a startup script, which is what makes an auto scaling group possible at all.
  • Built for remote administration. SSH is the normal way in, not a fallback.
  • It is what the software targets. Nearly every database, web server and runtime is developed on Linux first.

11 File permissions

Linux is multi-user, so every file records what three different classes of person may do to it.

Three classes (owner, group, others), each with three permissions: read, write, execute. Nine bits in total, which is why ls -l shows nine characters.

The eight digits
OctalBinarySymbolicMeans
7111rwxEverything
6110rw-Read and write
5101r-xRead and execute
4100r--Read only
3011-wxWrite and execute
2010-w-Write only
1001--xExecute only
0000---Nothing
Combinations in daily use
ModeSymbolicUsed for
755rwxr-xr-xScripts and directories. Owner edits, everyone runs.
644rw-r--r--Ordinary files. Owner edits, everyone reads.
600rw-------Private files. Only the owner, at all.
400r--------SSH private keys. Read-only, owner only.
777rwxrwxrwxEveryone can do anything. Almost always a mistake.
Danger The .pem file trap

Download a key pair from AWS and it arrives world-readable. SSH refuses to use a key anyone else can read, and the error, "Permissions 0644 for 'key.pem' are too open", reads like the key is broken. It is not.

The fix is one command: chmod 400 key.pem. This is the single most common first-connection failure on EC2, and it is worth committing to memory now rather than at 2am.

Note Changing them

chmod changes permissions, numerically (chmod 755 file) or symbolically (chmod u+x file to add execute for the owner, chmod go-w file to remove write from group and others). chown user:group file changes who owns it, and needs sudo.
